# Data Source

**Dataset:** Online Retail (UCI Machine Learning Repository, ID 352)
**URL:** https://archive.ics.uci.edu/dataset/352/online+retail
**License:** CC BY 4.0
**Citation:** Chen, D. (2015). Online Retail [Dataset]. UCI Machine Learning
Repository. https://doi.org/10.24432/C5BW33

Transnational e-commerce transactions (Dec 2010 - Dec 2011) for a UK-based
online gift retailer, 541,909 rows, 8 columns: InvoiceNo, StockCode,
Description, Quantity, InvoiceDate, UnitPrice, CustomerID, Country. Real
messy retail data: cancelled-order (`C`-prefixed invoice) negative
quantities, ~25% missing CustomerID, missing Description, zero-price rows.

## Vendored sample

`data/online_retail_sample.csv` is a fixed-seed random sample (n=15,000,
`random_state=42`, pandas `.sample()`) of the full dataset, sorted by
(InvoiceDate, InvoiceNo). Vendored so the repo runs fully offline in
under 60 seconds; the full 541,909-row file (48MB) is not committed.

**License:** `data/LICENSE-dataset.txt` is the vendored CC BY 4.0 legal
text (fetched from creativecommons.org).

**Modified from the original (required disclosure under CC BY 4.0 §3(a)(2)):**
1. Sampled to 15,000 of 541,909 rows (see above).
2. `CustomerID` is quasi-PII (a per-shopper identifier) - every value is
   replaced with `sha256(salt + original_id)[:16]`. The salt is a
   one-time `os.urandom(16)` generated at vendoring time and discarded -
   it is never written to disk or committed, so the hash is not
   reversible. Grouping/join semantics are preserved (same original ID
   always maps to the same hash within this file); the original numeric
   IDs cannot be recovered from the vendored data. Null CustomerIDs
   (guest checkouts) remain null.

## Known data-quality issues

- Rows with no `CustomerID`: guest or unlinked checkouts.
- Rows with no `Description`.
- Negative `Quantity` rows: returns and cancellations (`InvoiceNo` starts with `C`).
- Rows with `UnitPrice` of zero: free items, adjustments or data-entry artifacts.
- A few exact duplicate order lines.

The pipeline measures these (see `pipeline/run.py` and `data/quality_baseline.json`); counts are not repeated here.
