# retail-metrics-acceptance

Proves: each stakeholder requirement for a retail metrics layer is an executable acceptance test, and a planted bad row is caught. Verify in 60s: `make test`.

A UK online gift retailer's stakeholders ask for revenue trends, top products per country, repeat-purchase and retention figures, cancellation rate and average order value. Queries alone do not show that a number is right or that the data under it is sound. This repo answers each request as a SQL view, a user story with Given/When/Then criteria, and a pytest id that executes it, with a quality gate in front that stops the pipeline on bad rows.

## Run it in 60 seconds

```
make test       # acceptance tests, pipeline tests, doc drift tests
make selftest   # plants a duplicate key and a NULL join key, expects the gate to go RED on both
make regen      # rebuilds out/metrics.json, the dashboard, docs/recommendation.md and the Results block below
```

Open `dashboard/index.html` in a browser. Requirements and acceptance criteria: `docs/requirements.md`. Trace from requirement to test: `SPEC.md`.

## Honesty Statement

- Data is a 15,000-row fixed-seed sample of the UCI Online Retail dataset (CC BY 4.0), with customer identifiers hashed. See `data/SOURCE.md`.
- Every number above is regenerated by `make regen` and checked by a drift test; none is typed by hand.
- Expected values in the acceptance tests are computed from the CSV in plain Python, not from the SQL under test.
- Requirements the trace table in `SPEC.md` marks GAP (a BI tool, statistics and A/B testing, spreadsheets, a cloud warehouse) are not claimed.
- Recommendations state what the data shows. No savings or revenue forecast is made.

## Limitations

- The sample is not the full dataset, so figures differ from any full-data analysis.
- The last month (2011-12) is partial: the data ends on 2011-12-09. Its month-over-month change is not comparable.
- Rows with no customer ID are excluded from repeat-purchase and cohort metrics and reported as a revenue share.
- Cancellation rate counts invoices; a cancellation is not linked to the order it reverses.
- Three exact duplicate order lines in the source are recorded in `data/quality_baseline.json`, not removed.
- No statistical testing: differences between months or cohorts are descriptive.
